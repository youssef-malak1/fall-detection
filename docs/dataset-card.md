## Technical facts

- Resolution **640×240**, 30 fps, H.264.
- Each frame is a **side-by-side composite**: left half = depth image, right half = RGB.
  The usable RGB frame is therefore **320×240** after cropping `x ∈ [320, 640)`.
- Clip length 1.8 – 13.3 s (median 3.7 s).
- Frames: 5 990 fall / 8 941 ADL (60/40 at frame level).

## The two traps in this dataset

1. **Camera duplication.** `fall-XX-cam0` and `fall-XX-cam1` are the same physical
   event. Splitting by file puts the same fall on both sides of train/test and inflates
   every metric. **All splits are done at event level (70 events).**
2. **Tiny sample size.** 70 events is far too little to train a deep video model from
   scratch. Consequence for the design: use a **pretrained person/pose model** as a
   frozen feature extractor and train only a **small temporal head** on top of it.

## Known limitations (to state in the final report)

- Acted falls by young volunteers, not real elderly falls.
- Single room / controlled lighting → domain gap.
- No subject IDs published → subject-wise generalization cannot be measured.
- Low RGB resolution (320×240) → coarse keypoints.

## Preprocessing contract (decided)

```
read frame (640×240)
  → crop RGB half  : frame[:, 320:640]        -> 320×240
  → (optional) crop depth half for later work  -> frame[:, 0:320]
  → resize / pad to model input
```
